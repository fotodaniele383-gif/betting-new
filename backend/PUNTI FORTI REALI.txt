2. PROBLEMA GRAVE: buildPlayerMetrics()

Questa parte:

let holdPct = 100 * (0.45 + 0.85 * spw);

è completamente arbitraria.

Perché è pericolosa

SPW → Hold% NON è lineare.

Nel tennis reale:

62% SPW → ~78% hold
68% SPW → ~90% hold

la curva è sigmoidale/logistica.

Tu invece usi:

hold = a + b*x

che distorce tantissimo:

servebot
WTA
clay grinders
matchup estremi.
FIX CORRETTO

Usa logistic calibration.

Esempio:

function estimateHoldPct(spw) {
    return 100 / (1 + Math.exp(-12 * (spw - 0.62)));
}

oppure:

const holdPct =
    100 * (
        0.02 +
        0.96 / (1 + Math.exp(-14 * (spw - 0.61)))
    );
3. BREAK% MODEL È TROPPO AGGRESSIVO

Questo:

1 - Math.pow(1 - rpw, 4)

esplode troppo.

Con:

rpw = 0.40

ottieni:

87%

che è folle.

Effetto

Il DR diventa artificialmente enorme.

Quindi:

overconfidence
troppi favoriti
handicap troppo aggressivi
under troppo spinti.
FIX

Usa una regressione calibrata ATP/WTA reale.

Esempio:

breakPct = 100 / (1 + Math.exp(-10 * (rpw - 0.36)));
4. DOMINANCE RATIO INSTABILE

Questo:

breakPct / (100 - holdPct)

esplode vicino a hold 100%.

Problema

Con:

hold = 95
break = 25

hai:

DR = 5

completamente ingestibile.

FIX

Clamp aggressivo:

dr = clamp(dr, 0.4, 2.5);

oppure:

dr = Math.log1p(dr)
5. estimateSetDynamics() È TROPPO SEMPLICE

Questo:
